# hooks/stop_gate.py —— 交付放行的兜底钩子

> **先看这一句**：钩子保证的是"每一份交付出去的提示词都过了机械检查脚本"，两条路径都适用。
> 轻量路径（默认）跑 `check_prompt.py --report`，全套路径跑 `verify_delivery.py --report`，两种报告钩子都认；
> 连报告都没有的**完整稿**，钩子会自己代跑一遍 `check_prompt.py` 兜底。装它不会把轻量路径逼成全套路径。

**一句话原理**：模型准备结束回复时，钩子把这次回复里每一份"本轮交付的视频提示词"各自算一遍 SHA-256，
去报告目录里找 `ready=true`、正文哈希对得上（`delivered_sha256` 或 `checked_sha256` 相等）**且不早于本轮用户消息**的报告。
它比对的是**提示词正文本身**，不是那行"交付校验通过"。

## 三层判定

对回复里的每一份交付单元，钩子按顺序走这三层：

| 层 | 情况 | 钩子怎么做 |
|---|---|---|
| **1** | 找得到本轮的 `ready=true` 报告，哈希一致、`created_at ≥` 本轮用户消息时间、`session_id` 相容 | **放行**，不出声。轻量的 `kind: "light"` 报告（`check_prompt.py --report`）与全套的 verify 报告（`kind` 缺失视为全套）一视同仁 |
| **2** | 没有报告，而且这一份是**完整稿**（≥3 个段落标题） | 钩子**自己跑一遍** `scripts/check_prompt.py`：有错误 → **打回**，stderr 里列出错误原文，并要求修好后自己跑 `check_prompt.py --report`；没错误 → **放行**，但带一条 `systemMessage`：「这份稿由钩子代跑机械检查通过（未核对素材标签、锁定台词、总时长与父稿），作者本轮没有自己跑检查。」 |
| **3** | 没有报告，而且这一份是**局部镜头或不带四段外壳的裸操作命令** | **打回**。钩子没有父稿，代跑没有意义；提示带 `--baseline`（只交部分镜头再加 `--partial`）跑 `check_prompt.py --report` 再交付。带四段外壳的操作命令有 ≥3 个段落标题，按第 2 层当完整稿代跑 |

报告**存在但早于本轮用户消息**、或来自**别的会话**，一律直接打回，不给代跑兜底——那是"旧稿冒充本轮"，不是"忘了跑检查"。
`ready=false` 的报告（作者跑出了错误）不算数，会回落到第 2 / 3 层。

**代跑时钩子怎么调脚本**：把规范化后的正文写进临时文件，用 `sys.executable -X utf8 scripts/check_prompt.py` 跑；
任务类型按正文推断（命令区或 `视频N` 附近有"向后延长 / 向前延长 / 续写"→ 延长，有"无缝衔接"→ 衔接，
有 `编辑视频N` / 替换 / 删除 / 增加 且出现 `视频N` → 编辑，否则 生成；`视频N` 带不带 @ 都认）；外壳按标题推断：有概述段 → 六段旧壳，只有结尾段 → 五段旧壳，两者都没有 → 不传 `--format`，按脚本默认的四段新壳检查。
钩子不知道素材集合、逐字锁、总时长和父稿，所以**不传** `--labels` / `--lock` / `--total` / `--baseline`——
这也正是代跑通过时仍要带提示的原因。

**机械检查行也要对得上**：回复里出现 `check_prompt 通过（…｜sha xxxxxxxx）` 这样的行时，那个短哈希必须对得上本轮
已匹配到的某份 light 报告（`delivered_sha256` 或 `checked_sha256` 前 8 位）；对不上就打回（不要手写检查行）。
代跑通过的稿没有报告，所以那种情况下也不能自己写这一行。全套报告匹配的单元不要求有这行。

## 它认哪些东西是"交付单元"（契约，和 SKILL.md「流程分级」、quality-gate.md 一致）

| 写法 | 钩子怎么对待 |
|---|---|
| ` ```text `、` ```prompt `、无语言标签的代码块 | 成品候选：内容像提示词就要有本轮放行报告 |
| ` ```quote `（引用旧稿做诊断）、` ```draft `（概念草案） | 不验收，也不算本轮交付 |
| ` ```diff `、` ```json `、` ```bash `、` ```sh `（工具输出） | 不验收 |
| 代码块**之外**的纯文本 | 照样扫描：完整稿（≥3 个段落标题，四段新壳与五段 / 六段旧壳都算）、局部镜头（镜头标题）、操作命令（`视频N` 附近有 编辑/延长/续写/衔接/替换/删除/增加）都算交付单元，有没有合法代码块都一样 |
| 表头（锁定 / 待你定 / 升级 / 翻译）、例外说明、变更摘要、"这镜是否固定"之类问题 | 普通文字，不是提示词，不受检查也不受"原样粘贴"约束 |

算哈希前，钩子会先从单元里删掉"交付校验通过（正文 xxxxxxxx｜需求 xxxxxxxx）"这行和首尾空行，再按 `verify_delivery.py` 的方式规范化，
所以纯文本正文后面跟一行交付行不会被误判。**成品一律用 ` ```text `**：裸文本贴稿虽然也被保护，但段落切分靠空行推断，容易多切一刀被打回。

## 本轮绑定

钩子从 `transcript_path` 里找最后一条 **user** 消息的时间 `T_user`（`timestamp` 字段；那条没有时间字段时退回 transcript 文件的 mtime），
要求报告的 `created_at`（缺失时用报告文件 mtime）**≥ `T_user`**；宿主 payload 与报告都带 `session_id` 时两者还必须相等
（报告里的 `session_id` 来自检查脚本运行时的 `AIGC_SESSION_ID` 环境变量，没设就是 `null`，这时不做会话约束）。
拿不到 `T_user`（没有 transcript，例如 Codex 只给 `last_assistant_message`）才退回 24 小时窗口，并在放行时附一句
`systemMessage`"本轮绑定较弱"。于是"上一轮通过的旧稿，在用户改了要求之后原样再贴一遍"会被拦下，提示为本轮要求重新检查。

一个脚本，两个宿主都能挂：Claude Code 靠退出码 2 + stderr 阻止，Codex 靠 stdout 的 JSON `{"decision":"block","reason":…}` 阻止。

## 安装

先建报告目录（两个宿主都要）：

```sh
mkdir -p ~/.aigc-video-gate
```

### Claude Code

合并进 `~/.claude/settings.json`（或项目里的 `.claude/settings.json`）：

```json
{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {"type": "command", "command": "python3 ~/.claude/skills/aigc-video/hooks/stop_gate.py"}
        ]
      }
    ]
  }
}
```

### Codex

按官方 hooks 文档（<https://developers.openai.com/codex/hooks>）合并进 `~/.codex/hooks.json`：

```json
{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {"type": "command", "command": "python3 /Users/你的用户名/.codex/skills/aigc-video/hooks/stop_gate.py"}
        ]
      }
    ]
  }
}
```

**这是追加，不是替换。** 两份配置文件里都可能已经有别的 Stop 钩子（状态栏通知、提交提醒之类）：
`"Stop"` 是一个**数组**，把上面那个 `{"hooks": [...]}` 对象**追加**到数组末尾，原有的项一个都不要删。
整份覆盖 `settings.json` 会把用户别的钩子和设置一起弄丢。改完用 `python3 -m json.tool ~/.claude/settings.json` 确认还是合法 JSON。
Codex 的路径写绝对路径；`~` 在那边不一定展开。Codex 的 `matcher` 对 Stop 事件无效，可以不写。

> **Codex 侧尚未在真实 Codex 会话里验证过**：字段、阻止方式都是按上面那份官方文档实现的，本地只用构造的输入自测。
> Claude Code 侧同样只用构造的 transcript 自测过（`tests/test_stop_gate.py`，61 项），没有在真实会话里跑过。
> 依赖它之前请按下面的清单在真实宿主里各走一遍。

## 环境变量

| 变量 | 默认 | 作用 |
|---|---|---|
| `AIGC_GATE_DIR` | `~/.aigc-video-gate` | 报告目录。钩子、`check_prompt.py --report` 和 `verify_delivery.py --report` 必须指向同一个目录，改了要一起改 |

报告超过 24 小时就不再被接受（按 `created_at`，缺失时按文件 mtime 算），`ready` 不是 `true` 的报告一律不算。
另有可选的 `AIGC_SESSION_ID`：跑检查脚本时设成当前会话标识，报告会记下它，钩子再和宿主给的 `session_id` 对一遍。

## 它能拦什么

- **改稿不重查**：跑完检查又改了正文，哈希变了，旧报告对不上，必须重跑。
- **没跑检查**：手工拼的提示词根本没跑过检查脚本，目录里找不到对应哈希的报告——完整稿由钩子代跑一遍兜底（错误照样打回），
  局部镜头和操作命令直接打回。
- **手写检查行**：显示出来的 `check_prompt 通过（…｜sha xxxxxxxx）` 对不上任何一份本轮 light 报告，拦下。
- **多贴一份**：一次回复贴了两份提示词、只放行了其中一份，每份单独核对，少一份就拦；合法代码块之外那份裸文本也照样查。
- **旧稿冒充本轮**：用户改了要求，助手把上一轮通过的旧稿原样再贴一遍——报告早于本轮用户消息，拦下。
- **假交付行**：显示出来的"交付校验通过（正文 xx｜需求 xx）"与已匹配报告对不上（正文短哈希写错也算），拦下。
- 裸文本贴的完整稿、局部镜头和纯文本操作命令（`编辑视频1，……`）：没有本轮报告一样拦。
- 只交付某几镜的局部修订：按导出的正文哈希核对（`--output-scope affected` 的 `delivered_sha256`）。
- 缺固定句、固定句不在最后一行、外壳不全但仍是提示词形状的稿：一样要有报告。
- 用户只要提示词（`--response-mode prompt-only`，成品不带交付行）：按正文哈希核对，照样受保护。
- 读不到最后一条助手消息（`transcript_path` 不可读且没有 `last_assistant_message`）：算无法验收，先拦一次。

## 它拦不住什么

- **手工伪造报告文件**：往 `~/.aigc-video-gate` 里扔一份 `ready=true`、哈希自己算好、`created_at` 填成现在的 JSON，钩子就会放行。
  报告文件不是运行签名，钩子只能核对"有没有一份对得上的报告"，不能证明它真的跑过。
- 报告里填写的语义判断是否正确、素材读取声明是否属实——那是 `verify_delivery.py` 也管不了的，只能靠专业审查。
- **代跑不等于作者跑过**：钩子代跑时不知道素材集合、逐字锁、总时长和父稿，所以 `--labels` / `--lock` / `--total` / `--baseline`
  这四类检查全都没做，六域审查、警告裁定、需求覆盖更不在内。看到"由钩子代跑机械检查通过"这条系统消息，就说明作者本轮
  **没有**自己跑检查：那份稿只过了最基础的文本不变量，素材编号对不对、锁定台词有没有被改、总时长对不对都没人核过。
- **局部稿的父稿关系**：钩子没有父稿，所以局部镜头和操作命令它只能打回，不能代替作者判断改得对不对。
- 回复里那些不是交付单元的内容（普通讲解、镜头表、诊断表、表头、例外说明、` ```quote ` / ` ```draft ` 代码块）不受检查，也不该受；
  代价是：真把成品塞进 ` ```draft ` 就绕开了检查，所以这套契约靠 SKILL 里的写法约定，不是防对抗设计。
- **第二次仍失败时不是硬阻断**：已经被拦过一次之后（`stop_hook_active=true`）仍然不通过时，为了不死循环钩子**放行**，但输出
  `systemMessage`"本次交付未经放行验收……这份稿只能算待验证候选"。这是失败降级：看到这条消息就说明那份稿没通过验收，
  只能当待验证候选，别直接拿去付费生成。
- **撤回已经显示出来的文字**：Stop 钩子只能让模型继续处理，不能把已经显示给用户的内容收回来，所以不要承诺"未验收文字绝不会出现在屏幕上"。
- 宿主本身没触发 Stop 钩子（没装、配置写错、脚本报错）时什么都拦不住；装完请按下面的清单实测。

## 真实宿主验证清单（两个宿主各走一遍）

装好之后在真实会话里跑这五件事，确认行为符合预期再依赖它：

1. **一次正确放行（全套）**：正常写一份提示词，跑 `verify_delivery.py --report ~/.aigc-video-gate/<时间戳>.json --output … --response …`，
   只粘贴 response 文件的内容 → 回复应当顺利结束，钩子不出声。
1b. **一次正确放行（轻量）**：跑 `check_prompt.py --prompt <正文.txt> --report ~/.aigc-video-gate/<时间戳>.json`，
   粘贴正文和那行 summary → 回复应当顺利结束，钩子不出声。
1c. **一次代跑**：不跑任何检查，直接贴一份合法的完整稿 → 应当放行，但看到系统消息"由钩子代跑机械检查通过……作者本轮没有自己跑检查"。
2. **一次拦截，以及拦截后仍失败的处理**：故意贴一份固定句不在最后一行（或镜号跳号）的完整稿 → 第一次应被打回，stderr 里能看到
   check_prompt 的错误原文（Codex 收到以 reason 作为续写提示的继续轮）；如果重试时还是没修，第二次应当放行但带出
   "本次交付未经放行验收"的系统消息，确认失败没有被改写成通过。
2b. **一次局部打回**：不跑检查直接贴一份只含某一镜的局部稿 → 应当被打回，提示带 `--baseline`（加 `--partial`）跑 `check_prompt.py --report`。
3. **一次检查后改稿**：跑完放行后手动改动正文里一个字再贴 → 应当被打回（哈希对不上），重跑放行后才通过。
3b. **一次旧稿冒充本轮**：上一轮放行过的稿，在新的一条用户要求之后原样再贴 → 应当被打回，提示"放行报告早于本轮用户消息"。
4. **一次局部交付**：`--partial --output-scope affected` 只导出受影响镜头 → 粘贴该成品应当通过，说明局部单元的哈希也被认了。
5. **一次"只要提示词"**：`--response-mode prompt-only` 生成不带交付行的成品 → 粘贴后应当通过，确认钩子不依赖交付行那句话。

顺带确认：`~/.aigc-video-gate` 里的报告会越攒越多，自行按需要清理；清掉 24 小时以外的旧报告不影响当前交付。
