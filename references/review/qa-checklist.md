# 「自检」：提示词与资产质检

> 用于路由"「自检」"：默认的轻量路径在头脑里核对适用项并跑 check_prompt，走全套路径的成稿按 quality-gate.md 内部执行适用检查（分法见 SKILL.md「流程分级」）；用户输入「自检」或明确要报告时展示结果。检查对象是当前对话里最近一份完整提示词及其有效修改，以及能读到的参考资产；成片观察走 `diagnose.md`。
> 读完必须产出：一句总体结论 + 一张综合表（检查维度｜结论｜关键依据或需处理内容）+ 必要的修改建议与待决问题。
> 经验采用与优先级见 [../lessons/README.md](../lessons/README.md)：分清"试过的"和"没试过的"；没试过的照常可用但不冒称已验证，专业方案按当前任务适配性判断。

## 怎么做

1. 先跑 `scripts/check_prompt.py --report ~/.aigc-video-gate/<时间戳>.json`（带对的 `--task`、`--total`、`--labels`；改稿带 `--baseline`，白模预演带 `--untimed`；`--report` 每次换一个新路径，装了 Stop 钩子时它就是本轮交付的凭据；报告机械结果；轻量路径以 check_prompt 无错误、警告已逐条裁定为放行条件；走全套路径的成稿最终以 `verify_delivery.py` 结果为放行条件，未运行则标未完成，不作为已验收成稿），做文本不变量检查（外壳、镜号、时码、素材集合、固定句与它在末尾的位置、泄露、引用性措辞）；脚本通过只说明这些不变量成立，不等于画面语义或成片通过。错误只报告，不因自检自动改稿。
2. 内部覆盖下方 A0 到 A7 与 1 到 30 项，多镜头定位到具体镜号。只有文件名、占位符或"参考图"字样不算看过图；要查像素、声音、视频内容就读取；读不到记"待验证"并说明缺项，不推测资产合格。没有成片不是文本不合格的理由。
3. 默认输出三部分，六个维度：意图与素材、构图与运镜、动作与表演、节奏与连续性、材质光影与特效、声音与交付要求。每行写本镜的具体关系、短句或可见事实，不抄检查标准；无意义的维度合并或省略。结论用 `符合`、`需调整`、`待确认`；素材确实读不到才用 `缺少证据`。不用"基本通过"藏问题。
4. 同一问题只展开一次，注明受影响镜头。用户明确要完整逐项表时才按 `编号｜检查项｜状态｜依据` 全部展开，状态为 `通过 / 不达标 / 待对齐 / 待验证 / 不适用`，不用"其余通过"。
5. 只问必要的问题：缺必要事实、硬约束冲突、用户保留的选择、越出授权的修法才集中列 Q1…；开放的普通选择自行判断。自检不授权改稿；已获修订授权时执行确定部分。沉默不是确认。
6. 复核只扩大到影响范围；用户取消或暂留的问题记未解决，不改记通过。
7. 不例行追加"尚未生成视频""效果待验证"；只在具体缺证据影响结论时说。

## 开跑前与资产（A0 到 A7）

| 编号 | 检查项 | 核对标准 |
|---|---|---|
| A0 | 这场戏讲什么 | 核心事件、人物关系、情绪或叙事目的、构图运镜意图明确，提示词与之相符；不懂就问，不猜剧情 |
| A1 | 人物资产 | 脸和全身信息清楚，按景别需要有侧背面、服装发型、局部；身份定义明确；单人独立图优先，脸漂移时有大头照；画风和皮肤质感符合项目基准；分辨率撑得住景别 |
| A2 | 场景资产 | 覆盖所需前中后景与活动区域；门窗通道位置清楚；光源方向、色温、阴影符合戏的要求；缺将被拍到的信息时说明；授权自由设计的部分作为设计，不冒充图中事实 |
| A3 | 道具资产 | 身份、外形、尺寸、材质明确；按动作需要有握持、使用、变形状态，与手部尺度和相邻镜头一致 |
| A4 | 三维布局 / 分镜图 | 若提供，景别、构图、站位、运动与意图一致；未提供且不需要时不适用 |
| A5 | 机位图 | 若提供或空间关系依赖它，检查相机位置、朝向、轴线、起点路径终点；无图不自动要求 |
| A6 | 风格、光影、特效、定场参考 | 每份参考负责材质、色彩、光线、特效形态还是交互写清；不能只写"照着做" |
| A7 | 音色资产 | 需要固定音色时角色与音频对应、可读取、用途明确 |

## 提示词 32 项

| 编号 | 检查项 | 核对标准 |
|---|---|---|
| 1 | 四段外壳 + 末行固定句 | 新稿的主体 → 场景 → 风格 → 情节四个标题齐全且顺序对，**不出现 `概述：`，也不出现 `结尾：`**（总览句写在情节段开头；**末尾只有固定句 `全片不添加BGM，不添加字幕。` 那一行**，它上面一行是普通正文、后面不再有任何内容）；已有稿修订按实际父稿继承外壳与父稿那句固定句（六段旧稿的修订仍是六段、必填词仍在概述段、固定句仍是旧句；五段旧稿的修订仍是五段）；最需要精准的素材在主体段最前；操作类必填词与官方约束句全在情节段开头的命令区、第一个镜头标题之前 |
| 2 | 素材职责 | 每份 `@图片N/@视频N/@音频N` 写采用什么、不采用什么；人物、道具、场景逐一命名绑定；编号与上传顺序对应；不漏用不错绑；多素材按场景选择不全部同框；无文件名、UUID |
| 3 | 切镜数量 | 明确几枚镜头，实际镜头数与计划一致；区分镜头数与切点数 |
| 4 | 单镜时长 | 已知总时长与各镜容量匹配，时码连续、总和正确；用户要求无时码或 UI 选时长时不强加；容量参考平均每拍 ≥0.5 秒这条用户实测线索（L064，不是通过保证，仍按动作依赖与可读性判断），台词按真实说话时间算 |
| 5 | 只写当前画面 | 每镜只有可见清单里的人、部位、物件；画外人物只用可见线索；上一镜已完成的写成现状；没有引用性措辞 |
| 6 | 动作容量与摄影 | 每镜可包含多个有序动作，时长与可读性成立；密度看平均每拍是否 ≥0.5 秒（用户实测线索 L064：模型多会以加速方式完成密动作，1 秒 2 到 3 个不同动作离谱）——这只是不因密度自动拆镜的依据，不是通过保证，加速可能牺牲可读性或漏动作，需要看清的动作单独给时间；摄影按用户默认有可见运动，固定需来源依据（用户明确要求，含用户确认作者提议 / 保护范围），作者不能自行固定 |
| 7 | 机位 | 每镜摄影机位置、高度、角度明确；主观镜头说明是谁的视角 |
| 8 | 构图 | 景别、人物位置（画面坐标）、画面重心、清晰与虚化范围明确；起帧构图容得下要表现的动作 |
| 9 | 镜头运动 | 固定或运动明确；运动写方式、方向、速度变化、跟随对象与距离、起止、结束构图；术语按三档处理 |
| 10 | 硬切逻辑 | 前后镜头动势、节奏、方向、叙事关系合理；大动势切固定镜头要核对意图 |
| 11 | 人物表演 | 眼神、表情、身体动作、朝向、语气、反应过程具体；必要的可见表现与情绪方向，不凑表现数量；没有裸露的情绪词 |
| 12 | 动作与交互 | 谁对谁做什么，顺序、接触、受力、反应清楚；关键动作拆到部位，其余概括；上下镜连续时间还是跳时 |
| 13 | 开始与结束状态 | 每镜开头状态、终点位置与姿态明确 |
| 14 | 镜头衔接 | 前后位置、朝向、动作阶段、运镜、声音接续合理；反打按世界空间重判左右 |
| 15 | 站位与行动衔接 | 全景切近景后其余人物按裁切或遮挡合理存在；人数与关系连续 |
| 16 | 光影与合成 | 光源方向、主体亮暗、接触影或纵深线索写了；参考图不带自己的光；切镜不移动光源 |
| 17 | 环境与特效 | 风雾雨雪烟尘的方向、速度、强弱变化；受体响应一致；不为填表加不存在的天气 |
| 17a | 空间的流动性 | 按实际驱动检查必要环境响应与残留；无驱动的环境可保持安静。摄影运动与环境运动分开，不用加风尘满足摄影要求 |
| 17b | 表演的流动性 | 多人或关系镜头里，主要角色之外的可见人物有活动或有动机的注意；主体的衣、发、持物随动作有响应；人物静止写了动机，不无故僵住 |
| 17c | 风格段五方面 | 画风与渲染、实际材质、光的层次、镜头语言、表演核心五方面均须判断适用性；适用的独立控制必须在正文中落实，不限定各写一句，可自然合并。没有人物的产品或空镜不补人物表演，没有相应材质或驱动不编造响应。省略的是不适用内容，不能省略适用控制；不适用依据留在内部审查。画质词只在末尾且前面已有具体句 |
| 18 | 对白 | 说话者、原台词与实际发音文本、语气、口型要求明确；同音替换有逐字映射并保留非替换部分；音色对应；画外音不强制嘴型 |
| 19 | 音效 | 有具体音效时写事件与时机对应；不自动加音乐 |
| 20 | 字幕、音乐 | 最后一行逐字是"全片不添加BGM，不添加字幕。"（五段 / 六段旧稿的修订仍用旧句"不添加字幕，不添加背景音乐。"，位置仍在结尾段），只写一次、后面没有别的内容；保留对白、旁白、必要音效 |
| 21 | 禁止项 | 默认不写否定句（自写预算 0 条，固定句不计）；只留确实没有正向写法的那一句，写进它管的那一镜的正文（或操作命令的命令句），不放末尾；脚本的每条否定提醒都要裁定，确认后 `--negative-exception` 逐句点名；用户锁定项保留；没有堆砌；多人时必须保证身份、数量、外貌区分和素材绑定明确，发现身份混淆风险时先用正向区分控制，确无等价写法且必要时才增加对应否定句，不强制每个多人场景写"双胞胎"句 |
| 22 | 空词与术语 | 没有高级感、氛围拉满、震撼这类空词；没试过的术语后面跟可见结果 |
| 23 | 焦点 | 每镜主体与焦点明确；转移时起点目标过程一致 |
| 24 | 特效设计 | 来源、路线、接触、退出四件事；形态、材质、运动特征具体；不只"颜色 + 名词" |
| 25 | 特效交互 | 谁施放、从何处出现、如何流动、涌向谁、命中后的变化；接收者与环境响应；构图能看清 |
| 26 | 风格 | 整组提示词与素材用一致的项目风格；风格有主次且各控制兼容；参考图写实时写明画风 |
| 27 | 长视频阶段 | 30 秒每阶段一个主要变化并写结束时可见状态 |
| 28 | 操作类 | 编辑写唯一母版、范围、目标数量、保持内容；延长写边界画面、运动趋势、声音连续；首尾帧关键帧逐张说明且画幅相同；宫格写继承结构；白模写粗细与继承项；无缝转场写两段职责、触发、过程、到达状态；一键成片写职责顺序动态风格声音 |
| 29 | 整体一致 | 所有镜头要求与用户约束互不矛盾；人物数量、服装、道具归属、空间方向稳定；不发明素材标签 |
| 30 | 表与成文一致 | 所有实际采用的镜头设计均在正文落实；正文、需求、专业审查与放行记录版本相符；没有"全部落实"这类自证句 |

## 报告收尾

只总结影响当前交付的结论；没有待决事项就结束，不硬加"需要你决定：无"。用户只要问题清单时遵从其展示要求，内部仍覆盖适用项。成片到达后进入 `diagnose.md`，不自动重跑整份文本表。
