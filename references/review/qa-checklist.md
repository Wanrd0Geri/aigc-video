# 「自检」：脚本、AI、人核三层，只列问题

> 用于路由「自检」。检查对象是当前对话里最近一份完整提示词及其有效修改，以及能读到的参考素材；成片观察走 [diagnose.md](diagnose.md)。
> 「自检」只出报告、不改稿：用户判断，模型提建议。轻量路径写稿时的六域核对（SKILL.md「流程分级」）不变；本文件只定义「自检」查什么、怎么报。
> 三层：脚本查格式，AI 查画面内容，人核层只列不判。`表#N` 对应用户《视频组提示词及资产质检表》第 N 项，方便组员对照。
> 经验采用与优先级见 [../lessons/README.md](../lessons/README.md)：分清"试过的"和"没试过的"；没试过的照常可用但不冒称已验证。

## 怎么做

1. **脚本层**：对当前正文跑 `scripts/check_prompt.py --report ~/.aigc-video-gate/<时间戳>.json`（参数口径同 SKILL.md「流程分级」：`--labels/--task/--baseline/--partial/--lock/--asks/--untimed`）。错误、警告逐条裁定。这一层管：四段外壳与固定句（含 表#20 字幕、音乐）、镜号时码（含 表#1 切镜数量）、素材集合与编号、否定句、总括保证句、镜内标签与画质词、机制词与发力过程、主体段动作、复读虚词密度、表演排队。脚本通过只说明这些成立，不等于画面通过。
2. **AI 层**：按下面三张表逐镜、逐切点、整稿过一遍，每一项实际对着正文判断，不因脚本通过而跳过。内部全查，报告只列有问题的。
3. **人核层**：写意图复述、素材实际读取情况与矛盾、固定提醒项。AI 在这一层不下"合格"结论。
4. 报告按「报告格式」写。同一问题只写一次，注明受影响镜头。用户明确要完整逐项表时才按 `编号｜项｜状态｜依据` 展开，状态 `通过 / 有问题 / 需人核 / 不适用`，不写"其余通过"。
5. 只问必要的问题（缺必要事实、硬约束冲突、用户保留的选择、越出授权的修法）；自检不授权改稿；沉默不是确认。
6. 不例行追加"效果待验证"；只在具体缺证据影响结论时说。

## AI 层：逐镜（每一镜过一遍）

| 项 | 对着正文判断 |
|---|---|
| 机位 表#7 | 摄影机位置、高度、角度能从本镜首句或全局段读出；主观镜头写了是谁的视角 |
| 只写当前画面（skill 项） | 每镜只写本镜当前机位、景别拍得到的人、部位、物件；画外人物可由画里人物的视线方向等可见表现与画外声等听觉线索交代，不能当作画里的人来写；上一镜完成的动作在本镜写成现状 |
| 构图 表#8 | 景别、人物在画面哪里（画面坐标或画框切线）、哪里清楚哪里虚；起帧构图装得下本镜要表现的动作 |
| 运镜 表#9（硬） | 按用户当次授权、松紧档与父稿保护范围检查起幅、运动方向和结束画框；默认新设计需写全，缺适用项才算漏。现有"更放"允许只给方向、不给终点切线；获准局部修改不得借自检改动受保护摄影。固定镜头核对用户明确要求或保护范围的依据（SKILL.md 用户偏好第 1 条） |
| 焦点 表#22 | 主体是谁、焦点在哪一层；有移焦时从哪到哪、什么时候 |
| 关键事件可见 表#8 | 本镜 1–2 个关键事件发生在画里看得见、有光的位置；那一瞬没有整幅遮挡、没有抢同一主体的另一个大动作（成文主规则第 2 条） |
| 表演过程 表#11 | 眼神、表情、身体、语气写的是过程（起头、变化、到哪为止），不是只有结果或情绪词 |
| 表演流动 表#11/#5（硬） | 只查本镜当前画幅拍得到的人：画里相关人物有可见的活动或注意对象，状态可延续；反应从实际可感知的词、声音或动作起头，能交叠的交叠，必要先后按感知、身体条件与观看目的裁定；画里人物的等、听、想有当前景别可见表现，回答或大动作可后起。新增描述写清已有动作未表达的触发、方向/关系、克制或必要终态；同义重复合并，多个部位共同构成同一动作可留；排队、省掉等待表演和堆写都列为问题，不按数量配额，也不把画外人物写进画里（成文主规则第 8 条） |
| 动作与交互 表#12 | 谁对谁做什么，顺序、接触、受力、结果清楚；关键动作写清哪个部位到哪 |
| 起止状态 表#13 | 开镜时什么状态，结束时停在哪、什么姿态 |
| 时长容量 表#2 | 本镜秒数装得下写的动作和台词（对白按真实说话时间；一条连续动作每拍 0.5 秒可行，不是保证，writing-rules 第 72 条）；装不下就列问题，建议减动作或加秒数（加秒数要问导演） |

## AI 层：逐切点（每两镜之间）

| 项 | 对着正文判断 |
|---|---|
| 硬切逻辑 表#10 | 前后动势、节奏、方向接得上；大动势直接切固定镜头的，列出来让用户确认意图 |
| 衔接 表#14 | 位置、朝向、动作阶段、运镜、声音接续合理；反打按世界空间重判左右，越轴的列出来 |
| 站位与人数 表#15 | 景别收窄后其余人按裁切或遮挡合理存在；人数、关系、道具归属连续；上一镜完成的动作在本镜写成现状 |

## AI 层：整稿（查一次）

| 项 | 对着正文判断 |
|---|---|
| 素材职责 表#3 | 每份 `图N/视频N/音频N` 的职责写在所属段、只写一次，采用什么不采用什么清楚；情节里只用同一短名；与用户说的上传顺序一致；没有漏用或错绑（脚本只查集合，职责对不对由这里查） |
| 配角不僵 表#5 | 主角以外、本镜当前画幅可见的人物有当前景别看得见的活动或注意；等待、倾听、沉思不能只写动机词，画里旁观者按各自实际感知的时机起反应 |
| 空间流动 表#4/#17 | 对非特写镜头，从场景本来就在动的元素写出至少一处（场景段一句共享的也算：已有烛火、帘布、水面等）；用户明确要求静态或场景确无可见驱动时不判漏、不发明天气或装饰动态。AI 自行判为确无可见驱动时，人核层按同类合并列一行供用户看，不逐镜重复。风雾雨雪已有时，其方向、强弱在人、衣、草木上一致；人和环境有接触时环境有响应 |
| 光影合成 表#16 | 人物受光与场景光源方向、色温一致；写了接触影或纵深线索；切镜不移动光源；参考图不带自己的光 |
| 特效 表#23/#24 | 不是只有"颜色 + 名词"；写了谁施放、从哪出、走什么路线、碰到谁、之后对方和环境怎样、怎么退出 |
| 对白与音效 表#18/#19 | 说话者、原台词、语气、口型要求；同音替换有逐字映射；音效对上事件与时机；不自动加音乐 |
| 风格一致 表#6 | 整组风格段一致；风格段只有画面质感，没有表演、运镜、时序；参考图写实时写明画风 |
| 前后矛盾 表#21 | 各镜要求之间、与用户约束之间不打架；人物数量、服装、道具归属、空间方向稳定 |
| 需求落实（skill 项） | 对照可取得的用户要求、已确认分镜、父稿保护项和已认可效果，逐项检查其具体落点是否在正文且未被改丢；缺证据时注明不能核对的范围，不用"全部落实"之类自证句代替实查 |
| 操作类与长视频（适用时） | 延长 / 编辑 / 衔接 / 首尾帧 / 宫格 / 白模按 seedance-operations 第 0.5 节必填项齐全；30 秒长视频每阶段一个主要变化并写结束时可见状态 |

## 人核层（只列不判）

- **意图复述**：一句"我理解这场戏讲的是……（核心事件、人物关系、情绪去向）"。AI 不判断对不对；用户看是不是把鸡写成了猴。
- **素材，三种结果，只列事实**：
  - 已读取且与提示词矛盾：写素材里的事实和提示词原句（图2 蓝衣，稿里写红衣）。
  - 已读取但覆盖不足：镜3 要背面，图2 只有正面；场景图没有这场戏要拍的区域。标"覆盖不足"，不叫矛盾。
  - 没有实际读取：只有编号或文件名的，列出来标"未读取"，不推测质量。
  - 图的美观度、画风统一、分辨率、lineup、cameramap 齐不齐：**不判断**，交给组员按质检表。
- **固定提醒（适用才列）**：单镜时长是否合导演节奏；特效样式导演确认了没有、有没有参考图（没有就先找参考反推）；风格词是不是项目测试通过的那套；需要固定音色的角色音频接上没有；成片出来要看人物是否发白、像贴上去。
- **无驱动判定（仅 AI 自行作此豁免时列）**：按同类镜头合并一行，如"镜2、4：判为场景确无可见驱动，空间流动未列问题，请核对"；有用户明确静态要求且已列依据的，不重复提醒。不得变成每镜固定报告项。

## 报告格式

```
结论：一句（必要时说明本次检查范围或关键证据缺口）
问题（N 条）：
镜3 ｜ 运镜 表#9 ｜ 默认新设计缺结束画框 ｜ 推到哪不知道，模型会自己停 ｜ 补"推到画框下缘切在腰带"
镜3→4 ｜ 衔接 表#14 ｜ 反打后罗大娘仍在画左 ｜ 越轴 ｜ 改到画右
镜2 ｜ 表演流动 表#11 ｜ "说完……才抬头" ｜ 排队，AI 感 ｜ 锚到"回来"两字上起头
整稿 ｜ 需求落实（skill 项） ｜ 已确认分镜要求镜2保留背篓落地，但正文漏写 ｜ 已认可动作丢失 ｜ 在获准范围内补回或列待用户处理
人核：
- 我理解这场戏讲的是……
- 素材：图1 已读（正面全身）；图2 未读取；图3 已读——镜3 要背面，图里只有正面（覆盖不足）
- 提醒：镜2 4 秒装两句台词加转身，紧；镜4 特效样式没有参考图；苏云音色已接音频1
脚本：check_prompt 通过（…｜sha …）；待裁定提醒 3 条：2 条误报已裁定，1 条（镜2 排队）已列入上面
```

- 报告直接写成普通文本，不整份放进代码块；上面的代码块只是示意格式。
- 问题行五列：镜号或切点 ｜ 项（用户表项写表#N；内部实查项写 skill 项）｜ 原句或缺口 ｜ 影响 ｜ 最小建议。旧清单编号只放文末维护对照表，不放给组员的报告行。
- 需求落实（原"表与成文一致"）引用实际可得的要求或确认记录及正文落点；无来源证据时写核对范围，不用一句"全部落实"宣称通过。
- 脚本的错误和裁定后仍成立的警告进问题清单，与同义的 AI 层问题合并成一行；已裁定的误报只在脚本行计数。
- 没问题的项不列；不写"其余通过"。不出六维综合表。
- 报告里引用提示词片段用 ` ```quote `，**不用 ` ```text `**（text 块会被 Stop 钩子当成本轮交付去验收）；要引用的原句以镜头标题、段落标题开头，或含"视频N + 编辑 / 延长 / 替换……"这类命令句时，也放进 ` ```quote `，不写进问题行。
