# 经验库使用说明

> 经验库是一等文件：写任何提示词前先读 `seedance-2.5.md` 里与本次题材相关的条目；成片诊断后先记一条观察，写入正式条目要有当次授权；观察有依据不等于修法有效。
> 读完必须产出：写法里实际用到的条目；若某条改变了写法，在提示词后的例外说明里用人话讲原因（不给编号）；诊断后给出一条新观察。

## 条目格式

`L### | 日期 | 分类/主题 | 现象 | 写法A → 效果 | 写法B → 效果 | 结论 | 置信度 | 来源`

- 分类/主题：第 3 列固定写成 `分类/原主题`，中间一个半角斜杠，例如 `景别与画外/画外人物`。分类只能用下面 12 个里的一个，选最主要的那个；跨两类的挂主类，不写两个前缀。主题仍是便于人看的短标签（画外人物、竖立屏障、力度词、时间戳、焦段、慢动作……）。**新写入的条目必须带前缀，由脚本强制**：`log_lesson.py` 的 `--topic` 不合规直接退出 1、不写入；`merge_lessons.py` 遇到来源条目缺前缀拒绝整次合并；`lint_lessons.py`（`tests/run_check_tests.py` 里有一项调用它）检查全库前缀与编号连续。

### 12 个分类（唯一维护位置，其它文件只列名字、不重复定义）

| 分类 | 什么时候 grep 它 |
|---|---|
| `打斗` | 交手、攻防、力度词、兵器接触与后果 |
| `多人与站位` | 两人以上同框、站位与朝向几何、换位、分身与重复角色、多角色各自动作 |
| `摄影` | 运镜、跟拍、横移、环绕、焦段、光圈、焦点调度、机位角度 |
| `景别与画外` | 景别大小、裁切边界、前景遮挡与构图占比、画外人物与画外声音、尺度取舍 |
| `特效与形态` | 能量、法术、水火烟尘粒子、气态与无实体、材质与形态词、液体路径、穿模 |
| `表演与对白` | 表情与幅度、动作写法（动词序列 vs 姿态快照）、台词的表演部分、情绪转折 |
| `光影与风格` | 光源方向与受光面、画风与风格漂移、色调与背景色块、风格段和镜内的分工 |
| `素材与参考` | 参考图/视频/音频的职责与摆放顺序、三视图与单人图、参考拍不到的面 |
| `操作命令` | 延长、续写、编辑、替换、衔接、首尾帧、白模、宫格这类官方操作 |
| `密度与节奏` | 时间戳、镜长与容量、动作密度与节拍、过载与漏动作 |
| `声音与文字` | 字幕、画面文字、音效范围、发音与多音字、音色 |
| `通用` | 跨题材都适用的写法原则与模型总体特性（舒适区、程度副词、失败词、名词吃掉细节、版本差异、历史成功线索） |
- 写法 A / B：尽量贴原句；只有一种写法时 B 写"—"。
- 来源：成片文件名、日期、官方文档名、资料名，或"用户 + 日期"——用户自己的实测反馈是合法来源，但要写清楚它没绑定具体成片（如"已试（用户多次实测，未绑定具体成片）"）；用户描述与本人观察分开写。来源要能定位：模型版本、实际提交稿（不确定写 UNKNOWN）、成片文件名或截图；缺的字段写"未知"，不用相近的东西冒充配对。原来的六档标注保留在来源列末尾的"（原标：…）"里，只作历史信息。
- 观察与修法分开：现象栏写成片里看到了什么；修法没提交过就在效果里写"→ 没试过"，不写成已验证。

## 证据与采用规则（唯一维护位置）

置信度只有两档：

- **已试**：本项目有能定位的成片或截图对得上这条记录（成片文件名、抽帧诊断或用户实测截图）。要把一条写成已试，必须有能定位的成片或截图，没有就是未试。
- **未试**：没有本项目的成片或截图。资料与官方说法、旧版测试题的输入、一次样本的历史记录、新写入或合并进来的条目都算未试。

采用规则一句话：未试的照常可用，但说话时要说明是没试过的写法；已试的也不等于一定成功；都不能覆盖用户锁定项。

原来的六档（外部经验 / 测试情境 / 假设 / 待审 / 初步 / 已验证）保留在来源列末尾的"（原标：…）"里，只作历史信息，不再决定采用优先级。数字上限（几只、几段、几秒）只在当次条件下成立，写成"本次选择"，不写成通用定律。同一条目被反向证据打破时在结论里注明，保留原编号，不抹掉来源。

## 案例与经验的分工

三层各管一件事，别互相抄：

- **主体 `SKILL.md` 与工艺卡 `../craft/` = 设计默认与方法**，每次都读。
- **经验库（本文件）= 模型对写法的反应**：哪种写法兑现了、哪种被吃掉、在什么条件下成立。按分类 grep，写任何提示词前读。
- **案例库 `../cases/my-cases.md` = 完整成稿的组织方式与句式样板**：每镜几句、先写什么后写什么、几镜怎么接力、否定句怎么分配。只在任务类型、时长、素材形态对得上时读**一条**的「可复用点」与「关联经验」，需要抄句式才展开它的提示词原文。

所以**知识不留在案例里**（留在那里没人 grep 得到）：案例「可复用点」的每一条只能是两种之一——**知识**必须带 `→ L0xx`（经验库已有对得上的就引用，先 grep 确认真的对应；没有就当场用 `scripts/log_lesson.py` 写一条**已试**经验，来源写"案例 M00x + 成片文件名"，再把编号填回案例）；**样板**标 `（样板）`，不需要编号。入库规则写在 `../cases/my-cases.md` 头部，`scripts/lint_cases.py` 检查（回归测试里有一项调用它）。同一件事两边都出现时，**结论以经验库那条为准，案例只负责句子长什么样**。

## 整理经验（升级与合并）

- 频率：**每新增约 10 条经验或 3 条案例跑一次**；用户随时喊「整理经验」也跑。
- 跑 `python3 scripts/review_lessons.py`（只读，不改任何文件），它列五样：被 2 条以上案例引用的条目、同分类里主题相近可能能合并的条目对、结论里写了"修正 / 见 L0xx"的条目、各分类条目数（超过 15 条的点名）、已经标了「已升级为规则」的条目。
- 清单只是候选，**由用户挑**，不自动改库。用户点头之后：
  - **升级**：把规则写进 `SKILL.md` 或对应工艺卡，并在原条目的「结论」列末尾加 `【已升级为规则：<文件> <节>】`，其它列一个字不动。
  - **合并**：保留编号靠前的一条，后一条的「结论」列末尾加 `【并入 L0xx】`；不删条目、不改编号、不腾编号。
  - 改完重跑 `scripts/lint_lessons.py`。
- **读法**：带「已升级」标记的条目照常会被 grep 到，**不用专门跳过**；但同一件事以 `SKILL.md` 或工艺卡里写的规则为准，经验条目只是这条规则的来源记录。

## 成功反馈自动记录

本用户已明确长期授权：“我评价某版效果好就自动记录”。用户明确评价某一版**成片**的实际效果好、满意、成功（“这版效果好”“这版成了”“就要这个效果”）时，视为已授权写入，直接记一条成功观察，不再逐次问“要不要写进经验库”。只说“还行”“再看看”“先这样”，或只认可提示词文字、只同意某个修改方案，都**不触发**。

- 用 `scripts/log_lesson.py` 写入，`--topic` 照常带分类前缀（`分类/主题`），`--confidence 已试`（有用户指认的那版成片就算能定位），`--source` 写成片文件名或版本标识加日期；定位不到具体文件时写用户反馈原话加日期，并在来源里说明"用户已反馈成功但当前缺少可核对成片"。
- 先从当前上下文定位**实际提交的那一版**提示词，不要把候选稿当成提交稿；版本、模型、素材职责里不确定的字段写 UNKNOWN，多个版本确实分不清时先向用户澄清是哪一版。
- 记录内容：现象栏写用户评价的原话和本次可定位的成功点，写法 A 写那一版实际用的关键写法，结论写在什么条件下成立。用户只说整体效果好时只记整体评价，不自行推断每镜、每个运镜或某个词分别有效。
- **同一版本重复赞许补充原记录，不重复添加新条目**；补充时在原条目的来源或结论里追加，不改原结论的口径。
- 成功案例按任务适配性供以后参考，不自动升级成通用硬规则，不自动改写工艺卡，也不自动提高词库里所有相关词条的理解度。写完简短告知记了哪一版、哪个成功点。

## 怎么用

1. 写前：**按本次题材 grep 两三个分类前缀就够了**；**禁止整份读**，也不读文件尾部兜底——新条目的前缀由 `log_lesson.py` 写入时强制、`merge_lessons.py` 合并时强制，不会有漏网的无前缀条目。例：对话文戏 `grep "| 表演与对白/" seedance-2.5.md`、`grep "| 景别与画外/" …`、`grep "| 密度与节奏/" …`；打斗 `打斗/`、`多人与站位/`、`摄影/`；特效 `特效与形态/`、`光影与风格/`；延长与编辑 `操作命令/`、`素材与参考/`。不确定挂哪类时加读 `通用/`，不要为"看看还有什么"把分类挨个 grep 一遍。
2. 写中：把“专业方案是否适合本镜”和“模型效果有多少证据”分开。前者根据目标、几何、材料、容量和控制关系判断；后者决定能否宣称某修法已被模型验证。未试的写法不自动降权，已试的也不自动最适合；有已知风险的写法按本次条件处理，不整词禁用。采用未试的修法时说明设计理由，不把猜测当定律；只在会影响用户选择时展示不确定性。经验不覆盖用户锁定项和已确认事实。
3. 写后（诊断）：先形成一条新观察；用户授权或会话约定允许写入时，用 `scripts/log_lesson.py` 追加，自动编号；`--topic` 必须写成 `分类/主题`（**脚本强制**：不合规就退出 1 并在 stderr 列出 12 个分类，不写入），例如：

   ```bash
   python3 scripts/log_lesson.py --topic "景别与画外/画外人物" --phenomenon "……" --a "……" --b "……" --conclusion "……" --confidence 已试 --source "……"
   ```

   同时按 `../lexicon/README.md` 的规则更新词库对应词条的理解度列，前提同样是有能定位的成片或截图。
4. 待实测 A/B 清单在文件末尾维护：做过的划掉并写结论条目。

merge_lessons.py 从别处合并进来的条目一律写"未试（合并待审）"，原标注保留在来源里；来源里只要有条目的主题列缺合法前缀，整次合并被拒（退出 1 并列出违规编号），先去来源里补前缀再合。维护时分别核对观察与修法，要改成已试必须有能定位的成片或截图。合理的新设计可依专业原则提出，但不得冒称模型实测结论或覆盖用户锁定。

## 写入后同步

经验库由 Claude Code 与 Codex 共用同一份文件（软链到本仓库）。用 `scripts/log_lesson.py` 写入之后运行 `bash scripts/sync.sh 记经验`，把新条目推到 GitHub；不推也不会丢，但换机器或另一边重新克隆时会落后。
